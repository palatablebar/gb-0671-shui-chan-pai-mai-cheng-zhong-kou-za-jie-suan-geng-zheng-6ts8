# 东港水产拍卖结算

给水产市场结算员处理双次称重、开拍准入、扣杂计价、结算更正与应付复核。

八个模块：称重采信、货品换算、毛皮配对、开拍准入、扣杂竞价、更正裁决、应付对账、结算归档。每个导航页均可重跑同一批数据，隔离行保留编号、原值、行号和原因码。

```sh
docker compose up --build -d
docker compose exec -T app pytest -q
```

浏览器访问 http://localhost:18240 。默认载入现场脏批，包含53条逻辑输入、重复表头、缺列、空值、重复冲突、缺皮重、毛重小于皮重等问题。切换“核验清批”或“旧编码批”后重跑。进入“开拍准入”看当天开拍结论：首拍05:30按点开拍17个货包，3号秤异常时段内的货包复秤后才补拍，5个配对隔离货包留在暂缓清单。进入“更正裁决”核对票00001：原应付1168.50CNY，更正后1285.35CNY，已付1168.50CNY，仅待付116.85CNY。

API：各模块 `POST /api/<导航英文名>`；完整运行 `POST /api/runs`，JSON参数可用 `dataset` 或 `csv_text`。查询历史 `GET /api/runs`，复核 `POST /api/runs/{run_id}/review`，传入当前 `revision`。封存下载只有 `GET /api/export/{run_id}` 一个入口。准入另有 `POST /api/admission/switch`（`run_id`+`policy`），`POST /api/admission` 带 `simulate: true` 时只做方案推演、不套用已开拍台账。

同输入和规则摘要生成相同批号，不新增重复记录；复核版本改变后旧版本提交返回409。SQLite保存在命名卷。可使用新卷名称重建演示数据，原卷保留。

定义见 `docs/DATA-DICTIONARY.md`，模块与测试映射见 `docs/DEPTH.md`。源码在 `app/`，业务样例在 `sample_data/`，测试在 `tests/`。不连接实际秤台和支付渠道。

采信页支持上传或粘贴CSV。完整源字节与参数随批次持久化，跨页通过run_id读取同一结果。`POST /api/runs/{run_id}/rerun` 读取该批不可变输入快照重新计算，规则未变时批号不变。切换另一示例则创建或复用另一批次。

## 开拍准入规则

- 每个场次只认开拍时点**之前已到达**的校准记录与称重证据；迟到记录不会回改已开拍场次。
- 原称重落在异常秤时段、且没有有效复秤的货包，只进暂缓清单，复秤到齐后才进下一场。
- 已开拍货包写入 `admission_ledger` 冻结台账（按交易日 `scope` 隔离），同批重跑、迟到校准记录或迟到复秤到达时按台账整行恢复：不换依据、不换场次、不重复上板。
- 未确认、配对隔离的货包不进入竞价范围，也不进计价总额；原始称重证据在“称重证据账”逐条留档，只标注用途，不删除。
- 切换方案先校验：已开拍货包若被撤板、换场次或换依据则返回 409，且不写入任何结果，原准入状态保留。
